# DataNex Clinical Database Agent

A natural-language interface to a clinical MySQL database, built with the **Model Context Protocol (MCP)**. Users can ask medical questions in plain Spanish or English and receive SQL-backed answers generated by an LLM.

## Overview

This project connects an LLM to a MySQL database containing de-identified clinical data from 300 patients. The system uses MCP to expose database tools to the LLM, which autonomously writes and executes SQL queries to answer user questions.

Two backends are supported:
- **Local (Ollama)** — runs Qwen 3.5:9B on-device, no cloud services needed
- **Cloud (AWS Bedrock)** — runs DeepSeek V3.2 or Claude Sonnet 4.6 via the Bedrock Converse API

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   User /    │────▶│   Client    │────▶│  MCP Server │────▶│   MySQL     │
│  Gradio UI  │◀────│  (Ollama or │◀────│  (FastMCP)  │◀────│  Database   │
└─────────────┘     │   Bedrock)  │     └─────────────┘     └─────────────┘
                    └─────────────┘
```

### How it works

1. The **MCP server** (`server.py`) connects to MySQL and exposes:
   - A **schema resource** — the full database schema with table descriptions, fetched once at startup
   - Four **tools**: `lookup_ontology`, `lookup_codes`, `list_distinct_values`, `execute_query`

2. The **agent** (`agent_ollama.py` or `agent_bedrock.py`) orchestrates the conversation:
   - Fetches the schema and builds a detailed system prompt with domain-specific rules
   - The LLM calls tools in a workflow: clarify (ontology) → discover (codes/values) → answer (query)
   - Up to 10 tool-calling iterations with malformed-call recovery and a final-answer fallback

3. A **self-healing mechanism** automatically converts exact-match conditions to fuzzy LIKE matching on text columns when results are empty.

## Prerequisites

- **Python 3.11+**
- **MySQL** running locally with the `tfm_datanex` database

**For the local (Ollama) backend:**
- [Ollama](https://ollama.com) installed with the Qwen model pulled:
  ```bash
  ollama pull qwen3.5:9b
  ```

**For the cloud (Bedrock) backend:**
- AWS credentials configured with access to Bedrock in `us-east-2`
- `boto3` installed (`pip install boto3`)

## Usage

### Web UI

```bash
python app.py
```

Opens a Gradio chat interface at `http://127.0.0.1:7860`. Type questions in the chat box or click example prompts.

### Terminal

```bash
python client.py
```

Interactive terminal loop — type questions and see SQL queries + answers printed inline. Type `exit` to quit.

To use the Bedrock backend instead of Ollama:

```bash
AGENT_BACKEND=bedrock python client.py
```

## Evaluation Pipeline

The evaluation is split into two phases to decouple expensive LLM inference from metric computation.

### 1. Generation

```bash
# Local backend (Qwen via Ollama)
python generate.py --runs 3

# Cloud backend (configure model via env var)
AGENT_BACKEND=bedrock BEDROCK_MODEL_ID=deepseek.v3.2 python generate.py --runs 3
```

Runs the agent on all 30 questions in `golden_dataset.json` and writes raw outputs (SQL, result rows, elapsed time) to `generation_results/`.

### 2. Scoring

```bash
python evaluation/evaluate.py
```

Reads the generation output and computes **Jaccard similarity** metrics:
- `jaccard_similarity_sql` — token overlap between agent SQL and reference SQL
- `jaccard_similarity_output` — value overlap between agent result rows and reference rows (schema-agnostic)

When `--runs N > 1`, also computes pairwise Jaccard between runs as a determinism score.

Results for three models (Qwen, DeepSeek V3.2, Claude Sonnet 4.6), each with and without the ontology tool, are stored in `generation_results/`.

## MCP Tools

| Tool | Purpose |
|---|---|
| `lookup_ontology(keyword)` | Maps Spanish clinical terms to database tables/columns via the OWL ontology |
| `lookup_codes(table, column, keyword)` | Returns distinct (code, description) pairs for coded columns (ICD, ATC, lab codes) |
| `list_distinct_values(table, column)` | Returns distinct stored values for varchar columns to avoid literal guessing |
| `execute_query(query)` | Executes a read-only SELECT/WITH query and returns JSON results |

## Example Questions

| Question | What it does |
|---|---|
| ¿Cuántos ingresos por ictus isquémico hubo en 2024? | Counts hospitalizations by ICD code prefix I63% |
| ¿Qué anticoagulantes se administraron a pacientes con fibrilación auricular? | Joins administrations with diagnostics (I48%) |
| ¿Cuál es el valor medio de HbA1c en diabéticos tipo 2? | Lab lookup + unit conversion (IFCC→NGSP) |
| ¿Qué microorganismos se aislaron en hemocultivos positivos? | Filters g_micro by sample type and positive flag |
| ¿Cuál fue la primera troponina tras un cateterismo cardíaco? | CTE + ROW_NUMBER pattern for first lab after procedure |

## Database

The `tfm_datanex` MySQL database contains 33 tables across these domains:

| Domain | Key Tables |
|---|---|
| Demographics | `g_demographics`, `g_exitus` |
| Episodes & Movements | `g_episodes`, `g_movements`, `g_encounters` |
| Diagnoses | `g_diagnostics` (ICD), `g_health_issues` (SNOMED) |
| Lab & Microbiology | `g_labs`, `g_micro`, `g_antibiograms` |
| Medications | `g_administrations`, `g_prescriptions` |
| Procedures & Surgery | `g_procedures`, `g_surgery` |
| Severity | `g_diagnostic_related_groups` |

## Configuration

Database connection is configured in `server.py`:

```python
db_config = {
    "host": "127.0.0.1",
    "user": "root",
    "password": "",
    "database": "tfm_datanex",
    "port": 3306
}
```

LLM backend is selected via the `AGENT_BACKEND` environment variable (`ollama` by default, `bedrock` for cloud). The Bedrock model can be overridden with `BEDROCK_MODEL_ID`.

## Technical Details

- **MCP Framework**: [FastMCP](https://gofastmcp.com) for the server, `mcp` Python SDK for the client
- **Local LLM**: Qwen 3.5:9B via Ollama (no API keys or cloud services needed)
- **Cloud LLMs**: DeepSeek V3.2 and Claude Sonnet 4.6 via AWS Bedrock Converse API
- **SQL safety**: Only SELECT and WITH queries are allowed; all other statements are rejected
- **Self-healing**: Exact-match conditions on text columns are automatically rewritten as LIKE when results are empty
- **Determinism**: All backends use `temperature=0`; Bedrock prompt caching enabled for Anthropic models
